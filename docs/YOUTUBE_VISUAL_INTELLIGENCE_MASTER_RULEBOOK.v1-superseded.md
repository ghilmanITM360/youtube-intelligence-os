## 0. THE RULES YOU MUST KEEP IN WORKING CONTEXT

These rules override convenience shortcuts in the analysis workflow, but not user permissions, platform restrictions, or applicable law.

- **R01 — MP4-only eligibility.** A channel is eligible only when at least one genuine, locally accessible, decodable `.mp4` reference video attributed to that channel exists. MP3-only, transcripts-only, URL-only, screenshots-only, frame-only, storyboards-only, and empty channel directories do **not** establish eligibility. Additional MP4s can increase coverage. Record excluded channels; do not analyze their content or browse for substitutes unless the user explicitly changes the scope.
- **R02 — Keep channel boundaries.** Choose the active eligible channel using an existing user priority order, if supplied; otherwise use the most substantially documented eligible channel and record the choice. Complete the active channel before the next. Do not blend other channels' visual rules.
- **R03 — Prior analysis first.** Search the full available workspace for analyses, shot maps, extracted frames, image libraries, project source, old scoring, errors, and renders. Read and reconcile prior work before rerunning computation. Reuse only after inspecting its evidence, freshness, completeness, and integrity.
- **R04 — Do not mistake file existence for proof.** Verify files are readable, correctly attributed, and contain the claimed evidence. Track `VERIFIED`, `PARTIAL`, `STALE`, `CONTRADICTED`, `MISSING`, or `INACCESSIBLE` at artifact and finding level.
- **R05 — No superficial summaries.** Every covered shot requires a precise visual reconstruction record: what is visible, where it appears, colors, layers, object shape, orientation, movement, timing, camera, transitions, masks, shadows, optical behavior, and verified/inferred construction methods.
- **R06 — Measurements beat adjectives.** Prefer coordinates in pixels and normalized percentages, dimensions, frame indices, intervals, colors, and motion samples. If you cannot measure, label estimates with uncertainty; never invent exact specifications.
- **R07 — Do the missing work.** After a short discovery and gap pass, execute the highest-priority missing extraction, annotation, asset specification, test, or repair. Do not repeatedly output plans while the same identified task remains actionable.
- **R08 — Evidence in every claim.** Cite local file path + video ID + `HH:MM:SS.mmm` or frame range; include screenshots/crops/measurements for consequential observations. Preserve link to prior analysis if reused.
- **R09 — Recheck before each major unit.** Read the mission lock (section 0), the current phase-specific rulebook section, and `AUDIT_PROGRESS.md` before starting a new video, scene batch, reconstruction, resume, or verdict. Recheck completed outputs against acceptance gates immediately after writing.
- **R10 — Durable checkpoints.** Update the progress ledger *after meaningful completed units*, before context compaction, and at the end of the session. Include exact next action, open issue, file paths, last validated video/scene, evidence and test commands. Persist to disk, not just conversation.
- **R11 — Troubleshoot actively.** On errors, inspect logs, look up precise technical guidance using Chrome/browser if connected or available web tools, test a targeted fix, and document outcome. Never claim a tool or site was accessed if it was not.
- **R12 — No fabricated results.** No guessed counts, false frame inspections, invented audio analysis, claimed 100% match, fabricated source-project details, or asserted passing render tests without executing them.
- **R13 — Audio limitation acknowledged.** Audio is **not a required semantic analysis stream** in this project. Extract or locate soundtrack as needed for time alignment only; use available transcripts and visually observed timing. Do not claim detailed sound-design/audio comprehension without an actual capable, validated analyzer.
- **R14 — Same-video reconstruction gate.** Select an already-analyzed short reference video or a representative short segment of an eligible MP4. Use its exact **reference** transcript and soundtrack timing where accessible. Build **fresh visual assets and animations**, not a copy of its footage, overlays, or traced reference frames. Render and compare side by side using the reference.
- **R15 — Independent generalization gate.** A well-matched existing-video reconstruction is not enough. Create at least one **new, original visual sequence** without using an existing shot as the composition template. Validate transfer of the inferred design/motion system.
- **R16 — Rights and release.** Reference audio, transcript, graphics, frames, and recreation outputs are **research/controlled-validation artifacts only** unless separately authorized/licensed. Never automatically upload/publish recreations using another creator's protected soundtrack or footage. New releases must use cleared rights and meaningful original contributions.
- **R17 — Keep operating.** Do not stop because one method fails. Use documented alternatives when possible, note blocked substeps, continue unrelated executable steps, and distinguish `BLOCKED` from `DONE`.
- **R18 — Do not silently finish at 80–90/100.** Score is a diagnostic. Operational GO requires critical gates and executed production tests, not merely a favorable score.
- **R19 — No deletion.** Never delete, overwrite, rename, move, or mass-clean user reference files. Write derived outputs to a segregated output tree. Do not commit/push or upload without the user's prior authorization and repository policy.
- **R20 — Be faithful to actual capability.** Only say you used Chrome, video readers, renderers, local folders, or browser services if those facilities really were present and successfully invoked. If unavailable, record limitation and proceed with supported alternatives.

3. Where is the evidence for the claim I am about to make?

## 1. PURPOSE, BOUNDARIES, AND DEFINITION OF SUCCESS

Goal: reverse-engineer all **observable** aspects of a target channel's production system from locally held MP4 reference videos and existing legitimate auxiliary materials. Deliver a complete evidence-backed visual grammar, recreatable scene specifications, original asset design methodology, animation recipes, editing/compositing workflow, and tested pipeline for **new, original** videos with comparable technical and creative sophistication.

Explicitly out of scope for core audit: topic research, broad SEO, general competitor summaries, audience demographics, keyword analysis, or transcript-only channel analysis. Transcripts are alignment tools and reconstruction references, not proof of how shots are made. Audio semantics and music-source identification are optional and should not block visual analysis.

**Three evidence levels must never be conflated:**

1. **Observed final image/video:** directly visible; can be measured.
2. **Reconstructable implementation:** a practical independently devised solution producing the visible result; may involve more than one possible implementation.
3. **Confirmed original creator method:** only verified through primary evidence such as original project files, credible behind-the-scenes disclosures or asset provenance.

“Exact description” means sufficiently **precise and reproducible specification of what the available pixels and frames show**, not mind-reading or a guarantee of recovering private tools, creative intent, true hidden geometry, or original keyframes.

## 2. INITIAL WORKSPACE DISCOVERY AND CHANNEL ELIGIBILITY

### 2.1 Scope discovery

Locate the user's working project and search only directories available to the current agent. Respect access boundaries. Inspect folders, files, manifests, media indexes, old reports, extraction outputs, rendered videos, references, transcripts and scripts. Avoid expensive reprocessing at discovery time.

Use a recursive inventory that can include files with these extensions: `mp4`, `mov` (supplementary only), `mkv` (supplementary only), `mp3`, `wav`, `m4a`, `srt`, `vtt`, `txt`, `md`, `json`, `csv`, `png`, `webp`, `jpg`, `svg`, `psd`, `ai`, `aep`, `blend`, `fbx`, `glb`, `obj`, `prproj`, `drp`, `pdf`, `zip`.

**Eligibility is based on MP4 reference video, not on folder name, channel URL, or count of transcripts.** Validate using a real decoder / `ffprobe`, not just the filename. If an MP4 is an unrelated sample or a corrupt placeholder, do not count it. Associate it to a channel using documented metadata, path, file provenance, or verified title/channel information; if attribution is unknown, keep it `UNATTRIBUTED` rather than guessing.

### 2.2 Required channel eligibility table

| Channel ID | Channel/folder | Valid local MP4 count | Total verified MP4 duration | Existing analyses | Attribution confidence | Eligible? | Reason |
|---|---|---:|---:|---|---|---|---|

Exclude a channel when `Valid local MP4 count = 0`. *Do not begin web-only analysis for excluded channels.* Do not fetch/download missing channel videos without user authorization.

### 2.3 Eligibility edge cases

- MP4 video + no transcript: eligible; visual analysis can proceed; textual alignment flagged partial.
- MP4 + separate MP3/other audio: eligible; prefer original MP4 as timebase.
- MP3 only: **ineligible**.
- Screenshots plus PDF storyboard but no local MP4: **ineligible**.
- Download URL but file not local: **ineligible** under current rule.
- MP4 exists but cannot be decoded: mark `INACCESSIBLE`, do not count it as a validated reference until repaired or reliably decoded.
- Multiple video folders belong to one channel: aggregate only with strong channel attribution.

## 3. RECONCILE AND REUSE ALL PREVIOUS ANALYSIS

Before doing new analyses:

1. Search relevant Markdown reports, scene CSVs, frame folders, asset manifests, technical notes, storyboard records, animation measurements, render tests, error logs and old completeness scores.
2. Inspect actual samples from each claimed output. Verify existing file paths resolve; verify source-video IDs and frame timings; check whether reports have evidence links.
3. Build a **prior-work register**: `path`, `claim`, `source MP4`, `last modification`, `verification check`, `status`, `defect`, `can reuse?`, `next action`.
4. Reuse `VERIFIED` components. Repair `PARTIAL` components rather than discarding valid work. Recalculate or rerun `STALE` or `CONTRADICTED` outputs with a stated rationale.
5. Cross-check duplicate outputs and different versions; prefer the variant with stronger evidence rather than the newest timestamp alone.
6. Identify which of the 18 major audit categories have trustworthy evidence and which remain gaps.
7. Immediately schedule and **execute** the first highest-priority missing analysis task after the short reconciliation phase.

**Do not:** delete prior artifacts; redo all MP4 extraction because one markdown report has a gap; create a fresh empty report that hides an older completed analysis; call a previous score verified without independent inspection.

Write `PRIOR_WORK_RECONCILIATION.md` and keep IDs mapping old findings to new canonical records.

## 6. FRAME-ACCURATE VIDEO DECOMPOSITION

Use reliable local media tools, e.g. `ffprobe`, `ffmpeg`, PySceneDetect and OpenCV when available. Record tool name/version, commands, parameters, input paths and output paths. Tools may be unavailable; report actual availability before reliance.

### Required extraction passes

**Pass 1 — Technical audit:** Stream probe, duration, FPS/timebase, dimensions, codec, audio stream existence, variable frame rate if applicable; frame decode sanity check.

**Pass 2 — Discovery:** Contact sheets/thumbnail sampling; detect candidate scene cuts; export `scene_candidates.csv`; manually inspect false positives, fast cuts, fade transitions and scene changes within a single continuous shot.

**Pass 3 — Full shot boundaries:** Produce corrected start/end frame/timecodes for all material cuts and significant within-shot events. Assign stable `video_id`, `scene_id`, `shot_id`.

**Pass 4 — Action-event sampling:** Around any moving element, reveal, transition, quick effect, pose change or camera move, inspect sequential frames at sufficient density, up to original frame rate when needed; do not rely on 1 FPS stills for timing.

**Pass 5 — Motion and camera:** Track foreground/background relative motion, object bounds, vectors, zoom/scaling, perspective changes, and continuity. Optical flow is an observation estimator, **not** proof of original keyframes.

**Pass 6 — Cross-check:** Verify each exported scene with original MP4 frame references, not just detector output.

Suggested tool probes (adjust paths and available tool versions):

```bash
ffprobe -v error -show_format -show_streams -of json 'INPUT.mp4' > 'probe.json'
ffmpeg -hide_banner -i 'INPUT.mp4' -map 0:a:0 -vn -c:a pcm_s16le 'reference_audio.wav'
scenedetect -i 'INPUT.mp4' detect-adaptive list-scenes
```

Do not claim an audio stream exists without probing. If audio extraction fails, inspect stream mapping/codec/error and try an appropriate alternative; keep visual workflow going.

### Every shot entry MUST have

`video_id | scene_id | shot_id | source_file | start_time | end_time | start_frame | end_frame | observed composition | objects | layer hypotheses | motion events | camera events | transition | audio-time relation (if available) | evidence frames | confidence | analysis status`

Do not call a scene fully analyzed if timing or important animated events remain uninspected.

## 7. EXACT VISUAL RECONSTRUCTION BLUEPRINT — MOST IMPORTANT

**This is not a short scene summary.** Every distinctive analyzed shot needs a production specification detailed enough that a competent independent artist/animation engineer can reconstruct the observable look and motion without opening the original MP4 for every decision. A final side-by-side check against the source remains necessary.

### 7.1 Required scene blueprint fields

1. **Identity and evidence:** channel/video/scene/shot IDs; local MP4 path; exact frame/timestamp span; proof images; source dimensions/FPS; confidence.
2. **Narrative visual function:** communicate what the viewer should understand, and what visual emphasis occurs (not unsupported mental-state claims).
3. **Canvas and layout:** pixel coordinate system, aspect ratio, background coverage, visible framing, crop, safe regions; positions (`x`,`y`), widths/heights in pixels **and normalized percentages**; alignment anchors.
4. **Every meaningful visible element:** indexed list of foreground, midground, background, props, text, shapes, characters, overlays, particles, highlights, UI elements, shadows, visual effects; refer to asset IDs.
5. **Geometry:** detailed silhouettes, relative proportions, outline thickness, corner radii, stroke endings, spacing, arrangement, orientation; estimated perspective and distortion.
6. **Color and typography:** sampled colors/gradients/material cues, plausible font metrics, size, weight, line wraps, spacing, outline/stroke, shadow treatment; mark unconfirmed font names as approximation.
7. **Character fidelity:** body/head/limb proportions, pose, facing angle, expression, hand position, gestures, clothing folds, visible parts, occluded areas, skin/clothing colors; explicit pose changes during shot.
8. **Layers:** render order, matte relationships, alpha boundaries, occlusion, separated parts for animation, estimated layer count/range and layer purpose; distinguish measured vs proposed structure.
9. **Camera and space:** static versus simulated 2D/2.5D versus true 3D (observed evidence); framing, perspective, apparent focal properties, parallax, camera path, scale changes, depth relationships.
10. **Lighting/compositing:** gradients, contact shadows, ambient shadow, drop shadows, glow, particles, grain, depth of field, reflections, blur and motion blur; specify how to reproduce.
11. **Motion timeline:** frame/time where each object appears, changes, transforms, overlaps, reveals, exits; sampled positions and scales at meaningful key moments; easing shape and approximate velocity/acceleration when measurable.
12. **Transitions:** outgoing and incoming compositions, timing overlap, masking strategy, wipe/shape geometry, continuity, color and camera bridging.
13. **Asset production:** original/stock/AI/procedural *evidence if available*; recommended independent creation workflow; separated files needed; variants/views/poses; editable source preference.
14. **Production implementation:** plausible tool-independent recipe; vector layers vs 3D models vs cutouts; compositing order; control parameters; export specs.
15. **Recreation QA:** acceptance screenshots, expected final state, frame intervals to compare, visual errors to watch; unresolved unknowns.

### 7.2 Minimum visual description quality

**BAD:** “Blue background. Cartoon person moves. Camera zooms and a yellow arrow appears.”

**GOOD (illustrative values only; NEVER mistake for actual channel facts):** “Canvas 1920×1080; dark navy background approx #142740. A left-of-center character occupies x≈340–650 px, head center x≈490 y≈280. A 6 px pale-blue grid behind subject has ≈75 px spacing. Character's right forearm rotates toward screen-right during 01:04.120–01:04.520. On frame 1,539 a thick golden arrow first enters from y≈710; arrow length grows to ≈220 px over 11 frames with deceleration. A rounded yellow label at x≈1200 y≈405 reveals after the arrow; primary text about 62 px, black. Camera framing grows about 8% while grid shifts half as much as subject, consistent with simulated depth (not confirmed 3D). Shadow opacity falls as subject rises. Footage frames: `ref_frames/...`. Rebuild with named editable layers and compare frames 1539, 1545, 1550, 1565.”

Measured numbers must derive from actual frames. All examples in this rulebook are illustrative only.

### 7.3 Required detail escalation

For each unique scene technique use at least three annotation depths:

- **Level 1 — Scene summary:** orientation, purpose, subject, overall style.
- **Level 2 — Shot construction:** all asset IDs, geometry, layers, camera, transitions.
- **Level 3 — Frame/event timeline:** actual observed motion with event samples, key pose frames, entering/exiting items, error bars/uncertainty.

If a shot has no visible motion, write `NO MATERIAL MOTION OBSERVED` with evidence; do not fabricate motion.

### 7.4 Evidence-driven verification loop

For every blueprint: inspect source → write specification → independently reconstruct a reference frame or short motion fragment when feasible → compare side by side → correct geometry/colors/motion → log before/after evidence. A description is not `RECREATABLE_VERIFIED` until it has been tested or independently quality-checked with demonstrated sufficiency.

## 12. 2D / 2.5D / 3D SCENE CONSTRUCTION

Classify each shot as: static 2D, animated 2D, cutout 2D, layered 2.5D parallax, true 3D, mixed 2D+3D, generated moving imagery, or ambiguous. Provide **observational proof**: parallax disparity, perspective shift, shading continuity, visible surface rotation, occlusion, camera depth cues. Do not assert a 3D tool solely because a result looks dimensional.

### 2.5D checklist

- Backdrop / extended clean plate / hidden regions restoration
- Midground objects and planes
- Foreground isolated subjects
- Distinctively moving body or object parts
- Shadow pass and contact points
- Masks, alphas, depth ordering, edge bleed
- Proposed camera/plane coordinate system
- Relative parallax ratios and occlusion changes
- Frame-to-frame crop-safe margins and offscreen asset extension

### True 3D checklist

- Visible geometry, approximate scale and proportions
- Material roughness/specular/texture evidence
- Rig/pose or simulation needs
- Lighting rigs, shadow maps, contact shadows
- Camera projection, focal/FOV estimates, depth-of-field evidence
- Render passes, compositing overlays and effects
- Physics constraints if real-world behavior is depicted

Record feasible reconstruction alternatives and select one practical method for production tests.

## 13. ANIMATION AND MOTION GRAMMAR

For each material moving element, inspect frame-to-frame changes in translation, scale, rotation, deformation, opacity, reveal/mask, text counting, rotation axes and occlusion. For object and camera tracks, measure approximate sample positions at defined frames and durations. Assess ease-in/out, speed ramps, holds, anticipation, overshoot, follow-through, damped motion, morphing, rhythmic timing and motion blur.

A camera zoom is not equivalent to a pan or dolly; distinguish these. Use both foreground and background optical evidence when classifying apparent camera movements.

Record:

`motion_id | object_id | start/end frames | sampled transforms | path geometry | easing estimate | visual purpose | sync marker | dependencies | camera coupling | observed uncertainty | reference IDs | reproduction recipe`

For a reusable motion grammar supply parameterized original animation recipes, not unsupported original After Effects graph-editor values. Preserve original timing accuracy in full-reference reconstruction tests.

## 14. TRANSITIONS, EDITING, COMPOSITING, AND AUDIO-TIME ALIGNMENT

Audit hard/match/smash cuts, morphs, camera-swipe cuts, shape wipes, masks, fade/dissolve, particle bridging, object-based transitions, graphic crossovers and scene callbacks. Record first/last frame, shape geometry, overlap duration, incoming/outgoing composition and transition motion.

Measure cut density, shot duration distribution, explanatory hold time, visual event rate, pause/reveal cadence, and scene-to-scene continuity.

Audit compositing order, color finishing, gradients, glow, bloom, grain, vignettes, shadows, motion blur and final export. Note whether exact color pipeline is unavailable.

**Audio policy:** The main focus is visuals. If extracted soundtrack exists, use its duration, reference cut time, and observable waveform/markers as sync guides. Use existing transcripts when possible. If speech recognition or more sophisticated audio tools are unavailable or unreliable, label text/audio alignment confidence and proceed; DO NOT invent voice tone, exact SFX, instrument identity or mixing decisions. Optional sound metadata does not veto visual reconstruction. No requirement to do unsupported deep audio analysis.

## 16. WEB AND CHROME RESEARCH: MANDATORY WHEN A MATERIAL PROBLEM BLOCKS WORK

When an extraction, rendering, animation, visual design identification, or technical workflow problem occurs:

1. Reproduce and inspect concrete error, logs, command output or failed frames.
2. Identify likely root causes and write searchable, precise terms.
3. Search authoritative documentation first (tool docs, official developer docs, reputable technical tutorials); use community solutions with caution.
4. **If Claude in Chrome is actually connected**, use Chrome to inspect sources and test browser-based references; check connection through the available `/chrome` workflow where supported. Otherwise use available web research methods. Do not claim Chrome access if not connected.
5. Capture source URL, access date, problem summary, tested fix, command/patch and result in `WEB_RESEARCH_LOG.md`.
6. Apply smallest targeted fix and rerun the failing sample. If it fails, try a genuinely different method or reduce the sample to isolate cause.
7. After multiple unsuccessful distinct attempts, record `BLOCKED` with evidence and continue another actionable portion. Do not waste time repeating the same failed command.
8. Never upload private files to third-party sites without explicit permission. Respect browsing permissions, access rules and intellectual-property restrictions.

Research is a means of finishing analysis, not a substitute for inspecting existing MP4s. Do not browse a channel that was excluded under the MP4-only rule.

For each record store: `category`, `required evidence`, `existing verified references`, `coverage count`, `coverage % or reason unavailable`, `confidence`, `missing scenes/techniques`, `severity`, `can recover from existing MP4?`, `requires new original asset?`, `needs primary creator data?`, `active action`, `blocked?`, `status`.

Use `CRITICAL`, `HIGH`, `MEDIUM`, `LOW` for missing-data severity, and `KNOWN`, `INFERRED`, `UNKNOWN`, `NOT APPLICABLE` for knowledge type. **A file isn't a completed category just because it exists.**

Data target is **reproduction-ready observable knowledge**. Undisclosed project files and invisible creative intent can remain explicitly unknown if a practical reconstruction solution is validated.

## 18. QUANTITATIVE READINESS SCORING (DIAGNOSTIC ONLY)

| Dimension | Max points |
|---|---:|
| Representative video and shot coverage | 15 |
| Visual design system | 15 |
| Asset reconstruction readiness | 15 |
| Animation reconstruction readiness | 15 |
| Camera, depth and lighting | 10 |
| Editing, audio-time alignment and finishing | 10 |
| Visual decision-engine generalization | 10 |
| Executed independent reproduction validation | 10 |
| **TOTAL** | **100** |

Per dimension assign **0–5** with evidence: `weighted_points = max_points × score / 5`. No test execution means no executed-validation points. Report uncertainty and missing sources. For inapplicable components, transparently document allocation changes instead of silently granting full points.

Planning thresholds: **0–59 insufficient; 60–84 partially ready; 85–100 production-ready candidate**. There is **no automatic GO** from high score alone. Nothing is “100% cloned” by percentage metrics; “100%” may only mean all *defined, inspectable, material acceptance checks* passed.

## 19. REQUIRED SAME-VIDEO RECONSTRUCTION TEST (NEW USER REQUIREMENT)

This test is **mandatory** once representative analysis has reached a candidate-ready state (it may start earlier to expose gaps). Its purpose is to prove that scene descriptions and asset recipes are actionable, not just verbose.

### 19.1 Choose the reference test

Select an already-analyzed eligible MP4 with a short duration (ideally a 15–60 second reference video), or a coherent 15–60 second section of a longer video. Prefer a sample containing multiple high-value visual techniques. Record:

- local file path, video ID, duration, source FPS and aspect ratio;
- precise chosen frame/time range;
- available transcript text and its source;
- audio track provenance/availability and alignment confidence;
- the original visible assets and shot boundaries;
- intended reconstruction challenges.

**Use the same video's narration/transcript as the *timing and content reference*.** Do not invent a new script for the same-video comparison. If the transcript is incomplete, use the best verified existing version and label gaps. If rights allow, extract the original soundtrack from the reference MP4 for **private evaluation only**. If rights do not allow reuse or export of that soundtrack, produce a silent visual reconstruction with timeline markers or a legally usable placeholder and explain limitations.

### 19.2 Reference asset use restrictions

All new scene visuals must be created using the reconstructed production knowledge: vector drawing, original characters, individual assets, procedural effects, 2.5D layers, original 3D modeling or cleared stock. **Do not construct a 'recreation' by displaying the original video as a hidden/background layer, re-encoding it, tracing its protected frames into final output, or using copied source imagery as the finished animation.** Reference frames may appear in the QA comparison output, clearly marked and kept separate.

### 19.3 End-to-end test execution

1. Build a shot-by-shot visual script from reference transcript + visual evidence.
2. Construct a complete storyboard with frame-numbered compositions.
3. Derive asset manifests; specify every important asset/layer needed for visible movement.
4. Create missing representative original test assets and export editable sources when supported.
5. Set up animation layers/rigs/camera; implement observed motion grammar and transitions.
6. Place the reference audio timeline or timing markers; do **not** require semantic audio analysis to proceed.
7. Render a complete test video at compatible aspect ratio, FPS and duration.
8. Create side-by-side synchronized comparison with reference video (research only).
9. Review frames at cut boundaries, motion extrema, pose changes, key text reveals and selected regular intervals.
10. Measure and log visual mismatches: composition, color, typography, silhouette, poses, camera, timing, occlusion, shadow, transition, motion smoothness, missing elements.
11. Repair mismatches that stem from incomplete or incorrect documentation. Update the corresponding canonical scene blueprints and production recipes.
12. Re-render and repeat until target quality gate passes or explicit unresolved blockers are documented.

### 19.4 Validation requires actual outputs

Deliver: `test_plan.md`, `storyboard/`, `assets/`, `scene_sources/`, `recreation.mp4` (if rendering succeeds), `comparison/`, `visual_error_log.csv`, `qa_report.md` and reproducible commands. If unavailable, use status `NOT RUN` or `BLOCKED`, not `PASSED`.

A favorable screenshot similarity at one frame **does not pass animation quality**. Check trajectory, timing, transitions, persistent object identity, crop, alpha edges, and motion continuity.

### 19.5 Publishability caution

An internal reconstruction based on another creator's script or soundtrack is **not automatically publishable**. Do not upload the recreation or reuse their protected narration/visuals on YouTube without appropriate permission and rights review. Keep the *new original content* pipeline distinct from internal fidelity tests.

## 20. NOVEL-SCENE / ORIGINAL-VIDEO GENERALIZATION TEST

Once a same-reference reconstruction is evaluated, use the inferred channel production grammar on an **independent original topic or scene**. The production method must work without copying an already published shot composition or using a protected character/visual as the release asset.

Create at least two distinct original-scene tests, preferably across different dominant visual families; if time/resources require, one prototype may be an interim milestone but does not satisfy final GO. Each requires original visual brief, storyboard, style frame, editable asset inventory, implemented animation, final render, side-by-side **style/quality comparison** (not copied footage), and independent QA.

Test: consistency in illustration, color/typography, character identity, composition, depth, camera, transitions, pacing, and technical finish. If the system only knows how to reproduce an existing sequence, it is **overfitted** and not production-ready.

## 21. COMPLETION GATES — EXACTLY WHEN MAY THE AGENT MOVE CHANNELS?

### GO requires ALL:

- Verified local MP4 references and representative technique coverage.
- Relevant preexisting data reconciled and preserved.
- All material video/scene analysis in selected scope documented with source evidence, not one-line summaries.
- Reconstructable, detailed per-shot visual blueprints for sampled unique techniques.
- Assets, individual moving parts, layering, camera, motion grammar and compositing recipes understood enough to execute.
- Existing shortcomings resolved or nonblocking with a demonstrated alternative.
- Same-video reconstruction test actually rendered and passed established qualitative/quantitative checks.
- Original/new-scene generalization tests executed and passed.
- Score >= 85/100, no unaddressed critical blockers, rights boundaries stated.
- Reproducible project files, source references, progress and QA reports available.

### Verdict values

- **GO:** Ready for independent production at validated target scope; next eligible channel can start.
- **CONDITIONAL GO:** Useful partial system but some visual families/scenarios require explicitly defined restrictions; **do not silently move to next channel** under this rule.
- **NO-GO:** Missing essential evidence, actionable defects, failed/blocked tests, inadequate overall readiness.

Do not claim exact recovery of hidden original implementation. A score of 98/100 with unrun reconstruction remains **not GO**.

## 23. NO-SHALLOW-WORK ACCEPTANCE CHECKLIST

A reviewed shot is not `DONE` until:

- [ ] Original source MP4 and frame range are verified.
- [ ] The shot's visual components are indexed and cross-referenced to asset IDs.
- [ ] Colors, positioning and geometry are measured or accurately labeled as estimates.
- [ ] All **material** movements, pose changes, mask/reveal events and transitions are tracked.
- [ ] Camera motion and depth are supported by visual evidence; assumptions labeled.
- [ ] Layering and editable construction requirements are specified.
- [ ] Typography, annotations, shadows, compositing and edge behavior are described.
- [ ] Reference frames/crops or event-frame samples exist.
- [ ] A practical rendering recipe and source asset list are written.
- [ ] QA conditions and known unknowns are recorded.
- [ ] It is sufficiently precise for reconstruction or marked `NEEDS_DEEPENING`.

A channel is not done because every video has a one-paragraph description. Detailed technical evidence, independent reproduction, and new-content transfer are mandatory.
