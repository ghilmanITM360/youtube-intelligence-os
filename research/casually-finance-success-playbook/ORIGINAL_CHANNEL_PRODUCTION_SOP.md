# Original finance channel production SOP

This is our proposed workflow, grounded in explanatory patterns and known evidence weaknesses. The competitor's actual internal workflow is unknown. Every stage emits a reviewable artifact; missing critical evidence stops that stage. Solo creator owns all gates, using a second human for financial wording and sound where available.

## Gates, outputs and handoffs

| Stage | Required output | Pass gate / owner |
|---|---|---|
| Research idea | One audience question, decision/stakes, evidence pointers | Can state the question without alarm rhetoric; producer |
| Evaluate topic | 0–2 topic scorecard from topic report | >=9/12, evidence 2; producer |
| Check topical/news demand | Event date, source publish/update date, upload plan; Trends evidence or explicit unavailable | Do not equate news existence with search demand; researcher |
| Develop original angle | One falsifiable conditional thesis and counterargument | Adds an explanation beyond paraphrasing a headline; researcher/editor |
| Title candidates | 6 originals across mechanism/consequence/story constructions | >=9/12 title rubric; no unsupported premise; editor |
| Thumbnail concepts | 3 original roughs, 320/160 previews, comprehension notes | One dominant relation, truth/legibility pass; designer |
| Authoritative finance research | Claim ledger and saved source/version locators | Every material claim verified to stated scope or qualified/removed; researcher |
| Script | Original narration with fact IDs, satire/scenario labels, answer and counterevidence | Promise answered; no unverified certainty; writer |
| Narrative beats | Beat ID, question, new fact, intended understanding, timestamp estimate | Every beat changes understanding; editor |
| Storyboard | Every meaningful segment has starting/ending state, asset IDs, citations and motion purpose | No orphan narration, misleading chart or unsupported visual fact; designer |
| Generate assets | Approved original components and provenance ledger | Character/style consistency and rights checks; designer/developer |
| Authorized narration | Reviewed recording or authorized generated voice, pronunciation list and stems | Human verifies numbers/names, pacing and permission; narrator |
| Animate | Deterministic keyframe manifest and editable source | Frame-seek tests, truthful data animation, readability holds; animator |
| Edit and sound | Picture master, licensed/authorized music/SFX ledger, mix stems | Human listens start-to-end; speech clear, peaks measured, no accidental gaps; editor |
| QA | Finance/visual/audio/title-promise check records | No unresolved material accuracy/rights issue; creator + reviewer |
| Publish | Verified metadata, source links, chapters, subtitles, cover and privacy settings | Correct version uploaded; creator authorizes publication |
| Measure analytics | 24h / 7d / 28d snapshots, source/format segments | Actual Studio data when authorized; analyst |
| Improve next video | One prioritized change and test plan | Separate observed metric from guessed cause; producer |

The publish step is a future owner action; this research does not upload or schedule content. Safe timing and financial truth outrank speed.

## Financial fact-checking checklist

- Exact claim, priority, source URL/document, publication/update date, page/table and access date.
- Separate observed historical fact, source-reported estimate, forecast, opinion, satire and our calculation.
- Preserve stock versus flow, nominal versus real, price versus capitalization, adjusted EBITDA versus profit, rates versus yield, and units/denominator/population.
- Preserve report vintage, estimate revision, cohort/time window, index exceptions and conditional eligibility.
- Recompute arithmetic from verified inputs; arithmetic correctness cannot rescue wrong inputs.
- Check source contradicts, not only supports, central narrative; cite counter-scenario.
- Avoid universal promises, certain crises, forced-buying rhetoric or specific advice beyond evidence.
- Verify spoken wording/names/numbers with a human; ASR is not listening.
- On-screen source matches narration's scope. Put date/unit/scenario alongside animation.

## Character and visual QA checklist

Approved original face/hair/proportions; correct pose and gesture target; coherent outline/palette; natural joint limits; one reading hierarchy; no mask clipping or duplicate IDs; honest chart scale and dates; source-card legibility at 320px/160px; captions in safe region; explanation holds long enough for comprehension; seek forward/backward/random times; original art/provenance ledger complete. Do not confuse a scene count with meaningful information rate.

## Audio and publishing checklist

Human listens to entire master and verifies all named entities/numbers, authorized voice, clean edits, pronunciation, speech/music balance, clipping and silences. Measure mix loudness/true peak against the chosen delivery specification; no loudness target is inferred from competitor signal statistics. Use licensed/authorized music and SFX; record grants. Review subtitles for numbers/dates, title promise, thumbnail truthful implication, description citations, chapters, disclosures, end cards and actual mobile crop. Inspect an unlisted upload for picture/audio/subtitle synchronization before authorized public publication.

## Solo workflow and small-team scaling

Solo: make research ledger first, script second, storyboard third; approve a small component kit before detailed animation. Batch reuse by component type, then assemble by beat. Reserve a final source/voice pass independent of the first edit. Begin with one 5–8m mechanism and one self-contained Short extracted from the same research; do not count the reused research as independent evidence.

Three-person team: researcher/writer owns source/claim ledger; designer/animator owns assets/timeline; editor/producer owns mix, packaging and release gates. Shared contracts are claim IDs, beat IDs, asset IDs and integer frame timebase. A handoff is accepted only when its gate passes. Add team coordination only when throughput justifies it; no new backend, agent service or API is needed for this playbook.
